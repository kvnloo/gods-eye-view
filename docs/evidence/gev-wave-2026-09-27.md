## Objective

Increase contribution throughput without increasing maintainer review load.

This is deliberately **not** a "post as much as possible" wave. The repository
has a large feature queue and a maintainer workflow that rewards focused,
measured fixes, explicit ownership, regression evidence, security review,
feature-specific browser gates, and honest source/provenance claims.

The experimental unit is therefore:

```
one small owned fix
+ a few high-signal unblock reviews
+ collision/duplicate reduction
+ one shared-invariant design track
```

Do not open new upstream PRs from this board unless the lane explicitly moves
from CHECK to KEEP.

## Maintainer / contributor grammar observed

Recent community merges repeatedly exhibit these properties:

- one concrete failure mode;
- proof against current main, not only the contributor branch;
- explicit statements of what the change does **not** claim;
- old-vs-new or mutation evidence where practical;
- reuse of existing ownership boundaries rather than new parallel helpers;
- full baseline gates plus the feature-specific browser gate;
- source/licence/provenance truthfulness;
- maintainer follow-up kept small and contributor attribution preserved.

Good contributions are still closed when a smaller/better duplicate wins.
Collision avoidance is therefore a first-class acceptance gate.

## Wave 2 — shared invariant design

### #29 registered CCTV destination safety

Upstream design comment posted. State: **DISCUSS**, not code-ready.

Required product decision:

- remote/live catalog rows are untrusted and should get public-address
  validation + DNS pinning;
- operator file/env rows are currently an explicitly documented trust boundary
  and may intentionally reference LAN cameras.

Do not ship a blanket "public IP only" change unless maintainers explicitly
change the operator-configured policy.

Preferred implementation after agreement:

```
server-stamped provenance
  remote-public
    -> no userinfo
    -> resolve all A/AAAA
    -> reject any non-global answer
    -> pin connection to accepted address
    -> same-origin validated redirects only
  operator-configured
    -> preserve agreed local/private policy
```

Reuse/extract the proven DNS-address + pinned-connection pattern from the Radio
Browser transport instead of adding another independent CIDR policy.
