# GEV Field Lite · synthetic relief replay screen

**Status:** downstream fork experiment / LIMITED. Owner: [Field Lite #146](https://github.com/kvnloo/gods-eye-view/issues/146), [relief benchmark #152](https://github.com/kvnloo/gods-eye-view/issues/152), [Math372 #202](https://github.com/kvnloo/gods-eye-view/issues/202). Depends on the [validated relief projection PR #238](https://github.com/kvnloo/gods-eye-view/pull/238).

## User job

On an inexpensive phone/laptop, find **what changed** in a hypothetical relief plan when one piece of road-access evidence changes; distinguish the superseded baseline, inspect aggregated unmet need, and read the source references without starting the Cesium globe.

## Narrow implementation

- New **opt-in /field-lite/** HTML entry in the **existing GEV Vite build**. Existing root globe page and routes stay unchanged.
- No new provider, source-of-truth DB, permissions, webcam, voice, client location, Cesium dependency, or runtime dispatch path.
- The browser demo runs the existing bounded **synthetic capacity reference -> road outage replay -> validated Relief Field Packet**; it is NOT real Idai data, a map, a proven safe route or an OpenAI #120 algorithm implementation.
- A local-only JSON import accepts a **synthetic replay**, max 64 KiB, and validates it with `projectReliefOutageFieldPacket()` before display. Unknown/invalid data replaces the view with an unavailable notice; no upload/network or stored private data.
- Plain DOM `textContent` renders versioned before/after cards, known-only service and nearest-first control, aggregate unmet need, candidate assignment evidence, and explicitly non-current historical revision. Native `details` surfaces are keyboard and touch accessible, with responsive two-column/one-column layouts. All labels retain hypothetical/advisory nature.
- `build/vite.js` adds the normal multi-page Vite input. `build/panel.js` overrides input back to the original single `index.html` for the MCP panel with `inlineDynamicImports`. Separate source tests guard both input contracts.

## Validation and limits

- Local Node **22.16.0** with exact source blobs: **64/64 focused tests PASS** (60 inherited relief tests + four new view tests); remote file SHA must be checked before relying on published parity.
- Chromium desktop 1280x920 and mobile 390x844: two cards, native evidence disclosures, no horizontal overflow, valid local JSON accepted, malformed JSON rejected, restore-demo works, **zero external requests and zero JS errors**.
- Browser smoke used `set_content` and a **local inlined equivalent** of the modules because localhost navigation was blocked by the environment's administrator. This proves DOM behavior, *not* the Vite production/development route or CSP behavior.
- **Not run:** Node 24.14+/Node 26, pinned Prettier format:check, full npm test/build, package-boundaries, real dev/preview route, actual low-end Android/GPU interaction, offline caching/service worker, 2D map, GEV World Packet integration, humanitarian user studies or independent operator signoff. This remains a **draft**.
- Upstream [World Packet #880](https://github.com/bilawalsidhu/gods-eye-view/pull/880) and [access support #882](https://github.com/bilawalsidhu/gods-eye-view/pull/882) are independently owned review threads. This page does **not** copy or depend on their unmerged code.

## Falsifiable practitioner UX study — unexecuted

Run an opt-in, rights-safe blinded A/B comparison against ordinary map/spreadsheet pages using 3 fully synthetic or authorized packets. Four pre-registered questions: which revision is non-current? How many units are unmet by each aggregate zone? Which evidence reference changed? Does an `unknown` road count as open? Measure correctness (primary), time-to-answer (p50/p95), evidence discovery interactions, false certainty, and interaction/memory budgets on low-end Android, iGPU laptop and desktop. Do not measure identity-linked outcomes or reward disaster severity. Stop if the view performs worse or overstates actionable truth.
